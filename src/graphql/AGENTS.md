# src/graphql — GraphQL operations + codegen

## OVERVIEW

Operations defined in hand-written `.graphql` files; types/Documents generated by graphql-codegen (client preset) into `generated/`. Import everything from the `src/graphql` barrel. Schema is a local SDL snapshot synced from the backend.

## STRUCTURE

```
graphql/
├── queries/            # domain .graphql files (auth, admin, company, member, media, website, ...) + _fragments.graphql
├── generated/          # codegen output: graphql.ts, gql.ts, fragment-masking.ts, schema.graphql — DO NOT EDIT
└── index.tsx           # barrel: export * from './generated/graphql'
```

## CONVENTIONS

- **Add a query**: create/edit `src/graphql/queries/{feature}.graphql` → run `bun generate` (watch mode) → import the `XDocument` from `'src/graphql'`.
- **Operation naming** mirrors backend permission aliases: `Paginate{Model}s` / `FindOne{Model}` / `CreateOne{Model}` / `UpdateOne{Model}`.
- **Fragments** in `_fragments.graphql`, named after the model (`fragment Admin on Admin`, `fragment Pagination on Pagination`); query bodies spread them.
- **`.graphql` files are TAB-indented.**
- **Usage pattern**: NOT generated hooks — import typed `Document`s and use Apollo core hooks: `useQuery(PaginateAdminsDocument, {...})` / `useMutation(CreateOneCompanyDocument)`.
- Import hooks from `'@apollo/client/react'` (subpath, not `@apollo/client`).
- Pagination shape: `{ items, pagination { ...Pagination } }`; list pages use `fetchPolicy: 'network-only'`.

## ANTI-PATTERNS

- **Never hand-edit `generated/`** — regenerate via `bun generate`; oxlint already ignores the dir.
- **Never deep-import `src/graphql/generated/...`** — always the `'src/graphql'` barrel.
- **`schema.graphql` sync is manual** — there's no fetch script; copy it from the backend repo when the schema changes.
- **`bun generate` never exits** (watch mode); for one-shot use `bunx graphql-codegen --config=./codegen.config.mjs`.
